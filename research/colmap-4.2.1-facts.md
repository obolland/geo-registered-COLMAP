## 1. Position priors in the database
| Fact | Source |
|---|---|
| Table `pose_priors(pose_prior_id PK, corr_data_id, corr_sensor_id, corr_sensor_type, position BLOB, position_covariance BLOB, gravity BLOB, coordinate_system INTEGER)`. Keyed by DATA (sensor+id), not by frame: for an image, corr_data_id = image_id, corr_sensor_id = camera_id, corr_sensor_type = 0 (CAMERA). | EXP: sqlite_master dump after writing a prior |
| position = 3 doubles (BLOB). Covariance = 3x3 doubles (9 doubles, row-major), NaN when absent. gravity 3 doubles (NaN when absent). | EXP |
| Coordinate systems: `PosePriorCoordinateSystem` = UNDEFINED(-1), WGS84(0), CARTESIAN(1). WGS84 position order is (lat, lon, alt) (alt metres). | PY `.value`; SRC controllers/image_reader.cc: `Vector3d(*latitude,*longitude,*altitude)`, `coordinate_system = WGS84` |
| EXIF GPS (lat, lon, alt all present) is auto-written as a WGS84 prior during feature extraction, with NaN covariance (and gravity from EXIF orientation if present). Verified: exiftool-tagged test JPEG gave position [51.5 -0.1 30.], covariance all nan. Needs all three of lat, lon, alt. | EXP (t4.db); SRC image_reader.cc ~L299-320; DOC faq.html |
| The docs database.html page does NOT describe pose_priors (it lists rigs, cameras, frames, images, keypoints, descriptors, matches, two_view_geometries only). | DOC https://colmap.github.io/database.html |

Writing from pycolmap (worked in EXP):
```python
db = pycolmap.Database.open(path)          # creates if missing; db.close() at end
pp = pycolmap.PosePrior()                   # fields: position, position_covariance (3x3), coordinate_system, gravity, corr_data_id
pp.position = np.array([x, y, z])           # or lat, lon, alt for WGS84
pp.position_covariance = np.diag([sx**2, sy**2, sz**2])
pp.coordinate_system = pycolmap.PosePriorCoordinateSystem.CARTESIAN   # or .WGS84
pp.corr_data_id = pycolmap.data_t(sensor_id=pycolmap.sensor_t(type=pycolmap.SensorType.CAMERA, id=image.camera_id), id=image_id)
db.write_pose_prior(pp)                     # sig: write_pose_prior(pose_prior, use_pose_prior_id=False) -> int
```
Related Database methods (PY dir): read_pose_prior(id, is_deprecated_image_prior=True), read_all_pose_priors(), update_pose_prior, exists_pose_prior, num_pose_priors, clear_pose_priors. Images must exist first (write_image / extract_features / import_images). There is NO pycolmap function equivalent to C++ `UpdateDatabasePosePriorsCovariance`; set covariance yourself via read_all_pose_priors + update_pose_prior (or write it when creating).
Only one prior per image is allowed by the alignment code (duplicate prior for an image throws). SRC estimators/alignment.cc AlignReconstructionToPosePriors.
All priors must share one coordinate system when `use_prior_position` is on: `THROW_CHECK_LE(coordinate_systems.size(), 1) "Inconsistent coordinate systems defined in pose priors"` (SRC scene/database_cache.cc ConvertPosePriorsToENU).

## 2. pose_prior_mapper vs mapper
| Fact | Source |
|---|---|
| `pose_prior_mapper` = the incremental mapper with `options.mapper->use_prior_position = true`; extra options: `--overwrite_priors_covariance` (default 0), `--prior_position_std_x/y/z` (default 1 each, metres), `--use_robust_loss_on_prior_position` (default 0), `--prior_position_loss_scale` (default 7.82). Also takes all `--Mapper.*` options, `--input_path`, `--output_path` (must be an existing dir). | CLI `colmap pose_prior_mapper -h`; SRC exe/sfm.cc RunPosePriorMapper |
| With overwrite_priors_covariance=1 it rewrites the covariance of ALL priors in the database to diag(std^2) (permanent DB change). Without it, DB covariance is used; NaN/absent covariance falls back to `prior_position_fallback_stddev` = 1.0 m (PosePriorBundleAdjustmentOptions default). | SRC sfm.cc; SRC estimators/bundle_adjustment_ceres.cc ~L1030; PY `PosePriorBundleAdjustmentOptions().summary()` |
| Plain `colmap mapper -h` has no prior options. | CLI (grep prior -> none) |
| How priors act: database cache loads priors; (a) BA adds a position-prior residual per image only if >= 3 priors AND the reconstruction can be aligned to them (otherwise the 7-DOF gauge is fixed and priors ignored); handles rig non-ref images via `AbsoluteRigPosePositionPriorCostFunctor`; (b) when each model finishes, `AlignReconstructionToPosePriors` (RANSAC sim3, needs >= 3 registered images with priors) transforms it into the prior frame; if that fails it only restores original rig scale and logs a warning. If DB has zero priors the mapper logs "No pose priors" and returns without reconstructing. | SRC controllers/incremental_pipeline.cc L142-165, L394; estimators/bundle_adjustment_ceres.cc L950-1070; estimators/alignment.cc L240-285 |
| OUTPUT FRAME: metric and in the priors' frame. CARTESIAN priors: model in those coordinates exactly (EXP: synthetic scene, priors = 100*R*C+t; recovered centres matched priors to 6.7e-6, scale 100, nreg 12). WGS84 priors: priors are converted to local ENU with origin = lat/lon/alt of the FIRST prior read from the DB (pose_priors table order); the output model is in that local ENU (EXP: image 1 centre = [1.5e-6, -2.1e-6, 1.2e-6], others within 0.07 m of true ENU relative to image 1). Output is NOT in WGS84/ECEF; you must keep the first prior's (lat, lon, alt) as the ENU origin to go back to geodetic. ENU conversion is not stored in the model. | EXP (s.db, w.db); SRC database_cache.cc L494-530 (ConvertPosePriorsToENU), incremental_pipeline.cc L79 (`convert_pose_priors_to_enu = use_prior_position`) |
| pycolmap equivalent: no `pose_prior_mapping` function. Use `pycolmap.incremental_mapping(database_path, image_path, output_path, options=IncrementalPipelineOptions(), input_path='', ...)` with `options.use_prior_position=True` (also `use_robust_loss_on_prior_position` default False, `prior_position_loss_scale` default 7.815). Returns dict[int, Reconstruction]; writes to output_path/<idx>. Worked in EXP. No prior_position_std options on pipeline options: covariance comes from the DB. | PY dir(IncrementalPipelineOptions), docs strings; EXP |

| Focal length precedence (new camera) | (1) `camera_params` given -> used as-is, logged "Focal Length: 3000.00px (Prior)" (verified). (2) EXIF `FocalLengthIn35mmFilm` -> f35/43.27*diagonal_px. ## 5. Rigs
| Fact | Source |
|---|---|
| Command: `colmap rig_configurator --database_path DB --rig_config_path rig.json [--input_path RECON] [--output_path OUT]`; run AFTER feature extraction (extraction creates one trivial rig per camera). `--input_path` derives average intrinsics/extrinsics from an existing reconstruction when not in the JSON. pycolmap: `read_rig_config(path)` + `apply_rig_config(configs, database, reconstruction=None)`; `RigConfig.cameras` list of `RigConfigCamera(image_prefix, ref_sensor, camera, cam_from_rig)`. | CLI; PY; DOC https://colmap.github.io/rigs.html |
| JSON: list of rigs, each `{"cameras":[{"image_prefix":"cam1/","ref_sensor":true,"camera_model_name":"SIMPLE_RADIAL","camera_params":[...]},{"image_prefix":"cam2/","cam_from_rig_rotation":[w,x,y,z],"cam_from_rig_translation":[tx,ty,tz],...}]}`. Quaternion order is [w, x, y, z] (PY `read_rig_config.__doc__`: "Rotations are expected in the order [w, x, y, z]"); pose is cam_from_rig (maps rig-frame points to camera frame), translation in rig units. | DOC rigs.html; PY; EXP (my JSON parsed and applied) |
| Frame formation: image name minus `image_prefix` must be identical across the rig's cameras. Extraction with `--ImageReader.single_camera_per_folder 1` first gives one camera per camera-folder. | DOC rigs.html ("identical filenames across all folders"); EXP rig/r.db log: `Frame(frame_id=7, rig_id=3, data_ids=[(CAMERA,1,1),(CAMERA,2,5)])` |

## 7. Reading results in pycolmap 4.2.1
(All verified on a synthetic dataset, EXP.)
- `rec = pycolmap.Reconstruction(path)` (or `.read(path)`); `rec.write(dir)` (binary), `write_text(dir)`, `export_PLY(file)`, `transform(Sim3d)`, `summary()`.
- Counts are methods: `rec.num_rigs()`, `num_cameras()`, `num_frames()`, `num_reg_frames()`, `num_images()`, `num_reg_images()`, `num_points3D()`; ids `reg_image_ids()`, `reg_frame_ids()`.
- Maps (dict-like): `rec.rigs`, `rec.cameras`, `rec.frames`, `rec.images` (ImageMap), `rec.points3D`.
- Image: `im.name`, `im.image_id`, `im.camera_id`, `im.frame_id`, `im.has_pose`, `im.is_ref_in_frame()` (method). **`im.cam_from_world()` and `im.projection_center()` are METHODS** (call with parentheses). `im.cam_from_world()` returns `Rigid3d` with `.rotation` (Rotation3d: `.matrix()` 3x3, `.quat` = xyzw) and `.translation`; `.matrix()` gives 3x4. Camera centre in world = `im.projection_center()` (= -R^T t). Viewing dir `im.viewing_direction()`.
- Frame: `frame.rig_from_world` (property), `frame.rig`, `frame.image_ids`, `frame.has_pose`, `frame.sensor_from_world`. Rig: `rig.ref_sensor_id`, `rig.non_ref_sensors`, `rig.sensor_from_rig(sensor_id)` (= cam_from_rig; for ref sensor identity), `rig.sensor_ids`.
- Points: `pt.xyz`, `pt.color`, `pt.error`, `pt.track.length()`; `rec.points3D` keyed by point3D_id.
- Export recipe: `for iid, im in rec.images.items(): if im.has_pose: C = im.projection_center(); R = im.cam_from_world().rotation.matrix(); q = im.cam_from_world().rotation.quat  # xyzw`. Camera-to-world rotation is `R.T`.
- Database reading: `db.read_all_images()`, `read_all_cameras()`, `read_all_rigs()`, `read_all_frames()`, `read_all_pose_priors()` (counts `db.num_images()` etc. are methods).
