# Slice 1 review (commits 2be16db, 14316fb)

Verdict: no blockers. The maths is correct against an independent oracle, the Umeyama fix is the right form, and the deletions are clean. Ruff and format are clean, 21 tests pass. The findings are test-coverage gaps and one API hazard in `LocalFrame`.

## Blocker

None.

## Should-fix

1. `LocalFrame` is a frozen dataclass holding ndarray fields, so it is not really value-like.
   - Evidence: `LocalFrame.at(1,2,3,"X") == LocalFrame.at(1,2,3,"X")` raises `ValueError: The truth value of an array with more than one element is ambiguous`. `hash(frame)` raises `unhashable type: numpy.ndarray`. `frame.origin_ecef[0] = 0` succeeds on a "frozen" frame. The public constructor also lets `origin_ecef` and `ecef_from_enu` disagree with `lat_deg`/`lon_deg`/`h_m`.
   - Fix: make `origin_ecef` and `ecef_from_enu` derived (`field(init=False, compare=False, repr=False)` set in `__post_init__` via `object.__setattr__`, and `setflags(write=False)`), or store only lat/lon/h/datum and expose them as cached properties. Then `at()` becomes unnecessary. Frames will be compared and keyed (segment manifests, dedup) in later slices, so fix before slice 5/7 build on it.

2. The `_height` form switch is untested and the tests would not notice if it moved.
   - Evidence: mutation of `np.abs(lat) < np.radians(45)` to 89 deg or to 1 deg leaves all 18 geodesy tests green (run in a copy under /private/tmp/claude-501/rev/m). The switch itself is correct (see Verified), but nothing pins the poles, lat=0 and lat=+-45 against an external value; `EXTREMES` has only 89.9999 and -45.
   - Fix: add parametrised round-trip and external-value cases at exactly 0, 45, -45, nextafter(45, 0), nextafter(45, 90), 90, -90 with heights -1e4, 0, 1e5. Include a few ECEF/LLA pairs generated by pyproj and pinned as literals.

3. `ned_to_ecef` is only tested at lat=0, lon=0, so lat/lon wiring bugs pass.
   - Evidence: the test uses `ned_to_ecef(0.0, 0.0, ...)` only. At (0,0) a swapped lat/lon or a wrong sign on the lon terms is invisible for several axes. The `ned_to_ecef` assertion that the matrix rows are ordered `[e, n, -d]` is caught (mutation fails), but latitude and longitude dependence is not.
   - Fix: add one case at a generic point (for example 51.16, -4.12) comparing against `ecef_from_enu_rotation @ [e, n, u]`, plus an (N,3) case checking row independence. Also assert `ecef_from_enu_rotation` is orthonormal with det +1 and its up column equals the finite-difference ellipsoid normal (I verified 3e-10).

4. The "independent oracle" required by the plan is mostly self-referential.
   - Evidence: `test_ecef_to_lla_round_trips...` and the frame tests use the code under test on both sides. Only `lla_to_ecef` and one ENU vector have externally derived goldens. `ecef_to_lla` has no pinned external values, and `ecef_from_enu_rotation` has no external check.
   - Fix: see 2 and 3; pyproj values as literals with a one-line provenance comment is enough.

5. Reflection test is narrow and the degenerate paths are not covered.
   - Evidence: `test_reflected_data_...` uses a noise-free exact reflection and does not assert translation. Degenerate inputs: empty `(0,3)` raises `numpy.linalg.LinAlgError: SVD did not converge` after two RuntimeWarnings (not the documented `ValueError`); a single point or all-identical points raises `ValueError("a has no spread")` (fine, but untested); the shape check is untested; NaN input is not rejected.
   - Fix: guard `len(a) < 2` (or `< 3`) with a `ValueError`, and add tests for shape mismatch, one point, empty, and coincident points. Add a noisy near-planar reflection case and assert the cost is no worse than perturbed alternatives, and assert `t` (`b.mean - s R a.mean`). Optionally state in the docstring that rank-1 (collinear) input gives a valid scale but an under-determined R.

## Nit

0. README says `run_colmap_reconstruction.sh` is "replaced in slice 6", but docs/PLAN-TRACK1.md defines slices 0-5 only (headings at lines 24-80) and never mentions that script; slice 7 is referenced in prose but also has no section. Soften to "replaced in a later slice" or add the slice.

1. `ecef_to_lla(0, 0, 0)` returns `[nan, 0, nan]` with divide and invalid warnings. Evidence: run above. Not a real input, but either document "undefined at the geocentre" or raise.
2. API shape inconsistency: `ecef_to_lla(x, y, z)` takes three arguments while `LocalFrame.from_ecef`, `to_ecef` and `lla_to_ecef` outputs are `(..., 3)`; callers need `ecef_to_lla(*p.T)`. Accept `(..., 3)` (or add `LocalFrame.to_lla`) before slice 4 depends on it.
3. `ellipsoid` is a parameter on `lla_to_ecef`/`ecef_to_lla` but `LocalFrame.at` hardcodes WGS84 while carrying a free-text `datum` label ("ETRS89"). The datum string is never tied to an ellipsoid, so the "refuses to mix datums" check is label equality only. Acceptable now (the module comment bounds the GRS80 difference), but state in the `LocalFrame` docstring that the ellipsoid is WGS84/GRS80 for any label.
4. `test_enu_in_a_local_frame_matches_the_poc` pins `289.42645872267667, 95.68750531048772, 7.224728597654355`; the legacy code at 766539d gives `289.4264587227102, 95.68750531012596, 7.224728597945656` (differences 3e-11 to 3e-10 m, from the legacy per-point arithmetic order). Within the 1e-6 tolerance, but the comment says "outputs of the POC", so say these were recomputed or paste the legacy values. The four ECEF goldens match legacy to the last printed digit.
5. The test header cites commit 9cc9c68 while the review baseline is 766539d; both contain the same script, but one reference is enough.
6. `test_up_axis_tilts...` hides the numbers in the comment ("about 126 m", `111_250`, `-120`); compute the expected value from the sphere approximation (`r - sqrt(r^2 + d^2) `) or name the constants.
7. Slice 1 asked for a failing test first; the single commit 2be16db cannot show that. I confirmed the new reflection test fails against the old formula (`np.sum(sv)`: scale 1.99999999 vs best 1.99852 on that data) and passes with the fix, so the test does bite.
8. The reflection test data (std 50, 5, 1, exact reflection) is planar-ish but not the "nearly collinear" set the plan names; a (30, 0.001, 0.001) case is cheap to add.
9. Optimiser comparison trap for the future: a general optimiser can beat Umeyama only by using a negative scale, which makes the map improper; do not use such a check as an oracle without `s > 0`.

## Verified (no action)

- `lla_to_ecef` vs pyproj (EPSG:4979 to 4978), 20,000 random points over lat +-90, h -1e4..1e5 plus 0, +-45, nextafter(45), +-90, 1e-12: max error 9.3e-10 m.
- `ecef_to_lla` round trip: latitude error 2.4e-9 m, height 2.3e-9 m, ECEF round-trip 3e-9 m across the same set, including exact poles (returns lat 90, lon 0), the equator, 45 deg and neighbours, heights -1e4 and 3e7. Height from pyproj differs from this code by up to 1e-4 m on the same inputs; the code under review is the more accurate of the two. Degradation only deep inside the Earth (-6e6 m height: 9e-6 m).
- The `_height` switch at exactly 45 deg, lat=0 and lat=+-90 behaves; both forms agree at the boundary, and the discarded `np.where` branch's overflow is silenced.
- `ecef_from_enu_rotation`: orthonormal (5.6e-18), det +1, columns match finite-difference east, north and up on the ellipsoid to 3e-9; poles and (0,0) give the expected matrices.
- `ned_to_ecef` equals `R @ [e, n, -d]`; `(3,)`, `(N,3)` and `(2,4,3)` shapes work. `LocalFrame` `from_ecef`/`to_ecef`/`to` handle `(3,)` and `(N,3)`; round trip 4e-10 m at 1 km offsets.
- `umeyama`: the D matrix (flip the last axis when `det(U) det(Vt) < 0`) and `s = tr(DS)/var_a` are the Umeyama 1991 form; `t = mean_b - s R mean_a` is correct. I checked it against a multi-start optimiser (positive scale) over full-rank, near-planar, near-collinear and planar-exact sets with and without reflection: never beaten (to 5e-13 relative) and `det R = +1` always. Reverting to `sum(sv)` makes the new test fail.
- Deletions: gpx_to_enu_raw.py, generate_ref_images_txt.py (Umeyama, dt calibration, EXIF timing) and extract_colmap_poses_with_timestamps.py are gone; generate_path_cam_from_aligned_colmap.py, generate_tile_manifest.py and run_colmap_reconstruction.sh remain; nothing in the survivors imports or mentions the deleted scripts. README Legacy POC section now matches the directory contents. The remaining reference to `gpx_to_enu_raw.py` is the intended provenance comment in the test.
- Style: ruff check and format --check are clean; production code has one-line docstrings only where they carry a non-obvious fact; no dead code seen in either test file.
